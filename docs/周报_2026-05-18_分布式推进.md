- 结果：
  - server 正常监听
  - client 正常 join
  - 训练可以启动并完成

#### 延迟启动 client 验证

- 手动延迟启动 client，验证 `assign_client_id` 前缓冲机制
- 结果：
  - 所有 client 正常获得 ID
  - server 能正常进入训练
  - 无异常 traceback

#### 缺少一个 client 的超时验证

- 只启动 2 个 client，不启动第 3 个 client
- 初始问题：
  - server 卡在等待阶段，不开始训练，也不退出
- 根因：
  - join 阶段阻塞在 `receive()`，没有新消息时超时检查逻辑无法执行
- 修复后结果：
  - server 在约 `60.3` 秒后按预期退出
  - 明确输出超时日志和已 join client 信息
  - 已 join 的 client 也能正常收到结束信号并退出

#### 退出阶段 gRPC warning 观察

- 训练完成后观察到：
  - `StatusCode.UNAVAILABLE`
  - `Socket closed`
- 当前判断：
  - 属于退出阶段的非致命告警
  - 不影响当前最小验证通过结论
